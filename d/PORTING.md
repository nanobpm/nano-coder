# nano-coder in D: porting status

`d/` is a D reimplementation of nano-coder. It builds with LDC and dub, and it
runs alongside the Rust crate at the repo root. The Rust crate is still the
reference implementation, and the port reads the same `~/.config/nano-coder/config.toml`.

```sh
cd d
dub test                 # unit tests (all modules)
dub build -b release     # ./nano-coder-d
./nano-coder-d -p "list the *.d files here"
```

LDC is used because DMD has no Apple Silicon target. You need libcurl,
which macOS and most Linux distributions already have.

| `nano/config.d` | `config.rs`, `providers/mod.rs` (presets, `parse_model_spec`, resolve) | Supports `model`, `default_provider`, `temperature`, `max_tokens`, `system_prompt`, `max_iterations` and `bash_timeout_secs`. `[providers.*]` supports kind, base_url, api_key / api_key_env / api_key_command, default_model, headers, extra_body, drop_params, max_tokens_param, stream, temperature, thinking, thinking_levels, vision, replay_reasoning, timeout_secs, max_retries, retry_initial_backoff_ms, retry_max_backoff_ms and retryable_statuses. `[providers.X.models."M"]` supports temperature, thinking, thinking_levels and vision. Errors use Rust's wording, including the known-providers list. Kind aliases are accepted. Any other key is ignored. |
| `nano/qwen.d` | `providers/qwen.rs` | The Model Studio plan × region endpoint table, `endpointForUrl` and `isModelStudioUrl`. The `/settings` picker that uses them isn't ported yet (item 29). |
| `nano/muse.d`, `nano/providers/muse.d` | `providers/muse.rs` | UNOFFICIAL Muse Code. `--login muse` runs the device flow, mints a key (`onboard: true`) and saves it atomically with mode 0600 to `muse.json`, recording `refresh_token`, `expires_at`, `api_key` and `api_base`. The client adopts a fresher grant that a peer already saved and persists rotated grants only while the login is unchanged. Calls go to `{minted base}/responses` with Muse's client headers (provider `headers` override them). The catalog feeds `--list-models`, which drops image-generation, hidden and contributor rows, and the thinking-level and vision probes. `MUSE_AUTH_BASE_URL`, `MUSE_MINT_BASE_URL` and `MUSE_CLIENT_ID` override the defaults. | `nano/providers/demo.d` | `providers/mock.rs` | The `mock` kind: an offline keyword-driven client ("time", "list"/"file", "run"/"bash", "ask"/"question") that streams word by word and produces reasoning on "think". Unit tests use the scripted `MockClient` in `providers/mock.d`. |
| `nano/thinking.d`, `nano/temperature.d`, `nano/vision.d` | `thinking.rs`, `temperature.rs`, `vision.rs`, detection in `providers/openai.rs` | The most specific setting wins: session `/thinking`, then model, provider, global. Levels come from `thinking_levels`, else the endpoint, else the built-in Claude/GPT/o-series table, and are fitted to the nearest one with Rust's warnings. Request fields are `reasoning_effort`, llama.cpp `chat_template_kwargs`, and Anthropic adaptive `output_config.effort` or a fixed `budget_tokens` kept below `max_tokens`. `extra_body` overrides, `drop_params` drops, and the Anthropic temperature lock are handled (including the `output_config.effort` field-level override). Detection reads Copilot-style `/models` capabilities, llama.cpp `/props` and Ollama `/api/show`. It runs at startup and after `/model`, synchronously with 3 s timeouts, and only for Copilot and local or loopback servers. Rust probes in the background for every provider. Output: `/thinking [level\|default\|off\|reset]`, ACP `/thinking`, and `/model` replies with the temperature/thinking fields and warnings. `/context` shows the Temperature, Thinking and Vision lines. Banner warnings appear as in Rust. |
| `nano/http.d`, `nano/retry.d` | `providers/retry.rs`, transport | Uses libcurl (std.net.curl). It has an idle timeout via the low-speed limit and an incremental SSE parser. Retries follow `retry.rs`: errors are classified from the body (fatal codes such as `insufficient_quota` and `context_length_exceeded` never retry), the `retryable_statuses` list applies (408/409/425/429/5xx/529 by default), `Retry-After` and "try again in Ns" hints are honoured up to the max backoff, overloads back off longer, and jitter is applied. `max_retries` (default 5), `retry_initial_backoff_ms` and `retry_max_backoff_ms` are read. Streams ask for `text/event-stream`. A plain-JSON reply to a stream request is parsed whole. A stream that fails before its first event is retried; Rust also retries after metadata-only events, while D stops retrying once any event has arrived. |
| `nano/llm.d` | `llm.rs` | Message, ToolCall (invalid-argument preservation), LLMResponse, ChatRequest, the `LLMClient` interface and `ThinkSplitter`. |
| `nano/providers/openai.d` | `providers/openai.rs`, `providers/github_copilot.rs` | Chat Completions, streaming and non-streaming. With `replay_reasoning` (default on for Copilot reasoning models), `reasoning_content` is kept in `thinking_blocks` and sent back on the assistant message. The Copilot client takes the OAuth token from `api_key`/`GITHUB_COPILOT_OAUTH_TOKEN` or the saved login for `GITHUB_COPILOT_DOMAIN`. | `nano/tools/files.d` | `files.rs` | `read_file`, `write_file` and `edit_file` with the same schemas. Writes and edits are refused if the file wasn't read first or has changed since. | `nano/attachment.d` | `attachment.rs`, attachment parts of `llm.rs`, `context.rs` and the providers | Images are prepared against the model's vision limits: longest side 1568, byte cap (3 MiB by default) and accepted types. They are stored as `<sha256>.<ext>` in `<session>.attachments/` (a temp dir when there's no session) and referenced from the tool result. The session log uses Rust's `attachments` field. Each request sends the newest `max_images` images that are still intact, checking the hash and re-fitting to the current model. Older ones become placeholders: "sent earlier", or "no longer available" when missing or tampered. Chat Completions gets one `user` message of `image_url` parts after the tool-result run. Anthropic gets `image` blocks inside the `tool_result`. Copilot gets `Copilot-Vision-Request`. Stored names are validated, so a crafted log can't escape the directory. When an image must change, D shells out to `sips` (macOS) or ImageMagick, and fails with a clear error when neither is present. `sips` keeps EXIF orientation as a tag rather than rotating the pixels. WebP EXIF orientation isn't read. The context estimate assumes every stored image is still present. |

## Known differences from the Rust version

- **Sessions.** No index cache (`.index.jsonl`), titles, interactive picker,
  `--trajectory` or spill files. A crashed turn is reported on
  resume but not re-run.
- **Interrupts.** Ctrl-C cancels a turn and typed lines steer it (`nano/control.d`),
  but there is no prompt queue UI.
- **Anthropic** has only unit tests and a mock. The Copilot/OpenAI path was tested live.
  Signed `thinking` and `redacted_thinking` blocks are kept and replayed, as in Rust.

## Not ported yet (by Rust module)

Roughly in dependency order. Sizes are Rust lines.

1. ~~**Agent loop features**~~: modes and turn caps, `report_outcome`, `/queue`, reminders, context accounting with auto/smart compaction and the history tools are all ported. An output cap learned from a provider error (`max_tokens: N > M`) lowers later requests' `max_tokens` until `/model` switches. Rust also persists it per model; D does not yet (item 25).
2. ~~**Permissions vs. sandbox**~~: file-tool writes are held to the sandbox's writable roots (lexical and symlink-resolved path), as in Rust.
3. ~~**Sandbox**~~: Seatbelt done in `nano/sandbox.d`. Still to do: the Linux Landlock backend (until then the D build fails closed on Linux when a sandbox is configured).
4. ~~**Providers**~~: OpenAI Responses, Copilot routing and login, Muse, Qwen, the
   mock kind, retry classification and Rust's presets are done. Still to do: context-window
   and output-cap detection from `/models` and the Muse catalog.
5. ~~**Thinking, temperature and vision settings**~~: done (`nano/thinking.d`, `nano/temperature.d`, `nano/vision.d`).
   Still differs: with no `max_tokens` configured, D sends none, while Rust sends the model's
   published output cap or a large default (issue #114). D doesn't read the `/models` output cap.
6. ~~**Image attachments**~~: done (`nano/attachment.d`; see the module table for the differences).
7. ~~**Instructions, full version**~~: done (`nano/instructions.d`).
8. ~~**Skills**~~, ~~**Memory**~~, ~~**plan tools**~~ and the ~~**question tool**~~: done (`nano/skills.d`, `nano/memory.d`, `nano/plan.d`, `nano/question.d`).
9. ~~**Hooks**~~: done in `nano/claude_hooks.d` (project hooks run inside the sandbox).
10. **Sessions, rest** (`session_index.rs` cache and titles, `resume.rs` picker,
    `trajectory.rs` 1.3k). The format and `--list-sessions` are done.
11. ~~**ACP server**~~ (`acp.rs` 0.9k): done in `nano/acp.d`, except the commands listed above.
12. **Terminal UI, rest**: the line editor, input history and slash menu
    are done (see the table above). Still to do: `frame.rs` (a frame that
    keeps the input below streaming output), `status.rs` (status bar),
    `ui.rs` markdown rendering, Shift-Tab mode cycling, `turn_commands.rs`,
    `recents.rs`, `settings.rs` (`/settings`), and Ctrl-R search. Input typed
    before the editor takes over the terminal at startup goes through the
    kernel's line discipline, so an Enter there arrives as a newline.
13. **Packaging**: npm platform packages and release workflow for the D binary.

Notes for porting:
- Keep tool names, schemas and error wording identical to Rust. Models and
  nano-workforce depend on them.
- Each D module has its tests in `unittest` blocks. Port the Rust tests along
  with the code.
