# nano-coder in D: porting status

nano-coder 1.0 is a D reimplementation of the Rust nano-coder (up to 0.69, kept on the
`rust` branch and tagged `rust-final`). It builds with LDC and dub and reads the same
`~/.config/nano-coder/config.toml` and session logs. This file records how the port maps
to the Rust modules and where it differs.

```sh
dub test                 # unit tests (all modules)
dub build -b release     # ./nano-coder
./nano-coder -p "list the *.d files here"
```

LDC is used because DMD has no Apple Silicon target. You need libcurl,
which macOS and most Linux distributions already have.

## What works (the core loop)

| D module | Rust source | Status |
|---|---|---|
| `nano/toml.d` | (the `toml` crate) | A TOML subset with tables, dotted/quoted keys, all string forms, ints, floats, bools, arrays, inline tables and arrays of tables. Values come back as a std.json tree. |
| `nano/config.d` | `config.rs`, `providers/mod.rs` (presets, `parse_model_spec`, resolve) | Supports `model`, `default_provider`, `temperature`, `max_tokens`, `system_prompt`, `max_iterations` and `bash_timeout_secs`. `[providers.*]` supports kind, base_url, api_key / api_key_env / api_key_command, default_model, headers, extra_body, drop_params, max_tokens_param, stream, temperature, thinking, thinking_levels, vision, replay_reasoning, timeout_secs, max_retries, retry_initial_backoff_ms, retry_max_backoff_ms and retryable_statuses. `[providers.X.models."M"]` supports temperature, thinking, thinking_levels, vision, `name` and `base_url`. A model's `base_url` overrides the provider's, for regional OpenRouter workspaces (#169), and model entries merge field by field across layers as in Rust. `list_models = "configured"` makes `--list-models`, the `/settings` model picker (rows show `name (id)`) and `/model` suggestions use the configured models instead of the endpoint. `disabled = true` hides a provider from `/providers`, the pickers, suggestions and the ACP `/providers` list. Naming a disabled provider is an error. `--list-models` prints `provider/model` as Rust does. Global `thinking` and `vision` are supported too. `extra_body` is deep-merged as in Rust's `finish_body` (it never sets `temperature`), then `drop_params` are stripped. The presets and defaults are Rust's: `default_provider = "mock"`, `model = "gpt-4o-mini"` and `temperature = 0.7`. The presets are openai, anthropic, openrouter, fireworks, groq, together, deepseek, kimi (drops temperature, replays reasoning), mistral, gemini, github-copilot, muse, qwen (from `nano/qwen.d`'s plan/region table), ollama, llamacpp and mock. Legacy top-level `api_key`/`base_url` go to the default provider (OpenAI when that is mock), and explicit `[providers.*]` values win. Resolution validates `base_url` as `validate_http_base_url` does (http(s), no whitespace, controls, query or fragment). Mock needs no endpoint, and Copilot and Muse only need one when overriding. Errors use Rust's wording, including the known-providers list. Kind aliases are accepted. Any other key is ignored. |

The client uses `META_API_KEY`, or the saved key, or mints one, re-minting once after a 401. A stale OAuth token is refreshed first. The client adopts a fresher grant that a peer already saved and persists rotated grants only while the login is unchanged. Calls go to `{minted base}/responses` with Muse's client headers (provider `headers` override them). The catalog feeds `--list-models`, which drops image-generation, hidden and contributor rows, and the thinking-level and vision probes. `MUSE_AUTH_BASE_URL`, `MUSE_MINT_BASE_URL` and `MUSE_CLIENT_ID` override the defaults. | `nano/providers/demo.d` | `providers/mock.rs` | The `mock` kind: an offline keyword-driven client ("time", "list"/"file", "run"/"bash", "ask"/"question") that streams word by word and produces reasoning on "think". Unit tests use the scripted `MockClient` in `providers/mock.d`. |
| `nano/thinking.d`, `nano/temperature.d`, `nano/vision.d` | `thinking.rs`, `temperature.rs`, `vision.rs`, detection in `providers/openai.rs` | The most specific setting wins: session `/thinking`, then model, provider, global. Levels come from `thinking_levels`, else the endpoint, else the built-in Claude/GPT/o-series table, and are fitted to the nearest one with Rust's warnings. Request fields are `reasoning_effort`, llama.cpp `chat_template_kwargs`, and Anthropic adaptive `output_config.effort` or a fixed `budget_tokens` kept below `max_tokens`. `extra_body` overrides, `drop_params` drops, and the Anthropic temperature lock are handled (including the `output_config.effort` field-level override). Detection reads Copilot-style `/models` capabilities, llama.cpp `/props` and Ollama `/api/show`. Cell widths cover East Asian wide, emoji, ZWJ, combining marks and FE0F. `--resume last`, `/resume [ID\|last]` (the picker or, without a terminal, ID rows, excluding the current session) and `--list-sessions [--all] [--json]` are supported. The JSON output is byte-identical to Rust's for the same directory. Titles show as `title · last prompt`, and all echoed text is sanitized. |
| `nano/markdown.d`, `nano/mdblock.d`, `nano/mdinline.d`, `nano/mdtable.d` | `markdown.rs`, `mdtable.rs` | Terminal rendering of assistant markdown: styled headings, emphasis, strikethrough, inline code, links with dimmed URLs, fenced code between dim fences, nested/task lists with hanging indent, quotes, rules, and GFM tables (grid, wrapped, or stacked `Header: value` when narrow). ## Known differences from the Rust version

- **Sessions.** No index cache (`.index.jsonl`), titles, interactive picker,
  `--trajectory` or spill files. A crashed turn is reported on
  resume but not re-run.
- **Interrupts.** Ctrl-C cancels a turn and typed lines steer it (`nano/control.d`),
  but there is no prompt queue UI.
- **Anthropic** has only unit tests and a mock. The Copilot/OpenAI path was tested live.
  Signed `thinking` and `redacted_thinking` blocks are kept and replayed, as in Rust.
- **macOS linking.** `dub.json` exports only `_main` (`lflags-osx`). D emits thousands
  of weak template symbols; when they are exported, dyld coalesces each one against
  every loaded image at launch, which cost about 140M instructions per start.
  Exporting only `main` lets the linker bind them locally. Stack traces are unaffected.

- **Repository trust (D first).** A repository's own skills (the workspace skill
  directories and `ai.lock`) and its `.claude/settings*.json` hooks load only once the
  repository is trusted (`nano/trust.d`). An interactive start asks "Trust this repo?"
  once and remembers a yes in `~/.config/nano-coder/trusted-projects`; `-p` and piped
  runs skip untrusted resources with a note; `--yolo` and `--acp` trust without asking
  (the previous behaviour). Rust: nanobpm/nano-coder#146.

- **Network loss (D first).** A request that can't connect (DNS, refused, reset, timeout)
  waits for the network with backoff (1s up to 30s), doesn't use up `max_retries`, and
  continues until Ctrl-C. The wait is reported on one line: on a terminal or in the
  frame UI it is rewritten in place with the time spent waiting; elsewhere there is one
  line when the wait starts and one when the network is back. A reply whose stream drops mid-way is asked for again (up to 10
  times per step), and the partial text isn't kept. The Copilot token refresh waits the same
  way. Rust: nanobpm/nano-coder#148.

- **Timers (D first).** `timer_set` (`after: "30m"` or `at: "14:30"`, plus a `note` for
  the agent's future self), `timer_list` and `timer_cancel` let the agent come back to
  something later in the session, such as a CI run, a deploy or a review (`nano/timers.d`).
  The harness owns the clock. A due timer joins a running turn as a system note before the
  next model call. At an idle prompt it starts a new turn while nothing is typed; a draft left untouched for 60 s is set aside for the timer turn and restored afterwards (#178).
  With `-p` it fires only with `--wait-timers`, which sleeps until each timer is due and
  runs it; without the flag, timers left unfired are named in a note when the run ends.
  Limits: delays of 1 minute to 24 hours, and at most 10 timers at once. Timers don't
  repeat. A fired timer stays pending until the agent calls `timer_done` (or
  `timer_cancel`): while it is pending, a reminder listing it is added every 5 steps of a
  turn, so a timer that fires during focused work isn't lost. A timer only reminds the agent; anything it does next goes through the normal
  permission checks. Timers are a `timers` record in the session log, so `--resume` restores
  them, and one that came due while nano-coder was closed fires as overdue. `/timers` lists
  them and the status line shows `⏰ HH:MM`. Timers are off under `--acp`, which has no idle
  loop to fire them. Rust: nanobpm/nano-coder#150.

- **Ported from Rust 0.52–0.65.** Path-leading and multi-line prompts go to the
  model (#175); the mock provider is hidden (#176); the stream idle timeout defaults
  to 120 s (#180); ACP reports the turn's token usage (#177); compaction clips keep
  error lines (#161); `report_outcome(completed)` after an unchecked edit is bounced
  once (#158); search walks are resource-bounded (#160); the loop detector tokenises
  shell stages (#159); markdown renders `:emoji:` shortcodes (#181).
- **Ctrl-O (#156).** Expands or collapses the latest tool call/result or thought in
  the frame UI. D's transcript is printed bytes, so folds are in-band OSC 8770 marks
  the frame swaps in place. Since #248 a press expands the next batch of 20 folds
  going up from the bottom (all expanded: collapse all), verbose expands existing
  folds, and the expanded text lives in an anonymous temporary file rather than in
  memory; a thought still streaming can't be expanded.
- **Updates (#154, #172).** Interactive npm installs (`@nanobpm/nano-coder`, found
  through the global bin symlink too) check the registry at startup and hourly in the
  background, keep `update-check.json` in the D data dir, and hint once per version
  at an idle prompt. `check_updates = false`, `NANO_CODER_NO_UPDATE_CHECK`,
  `NO_UPDATE_NOTIFIER` or `CI` turn it off. `/update` re-checks and runs `npm install
  -g` attached to the terminal; other installs get the releases page. `/relaunch`
  execs the binary with `--resume <session>`. Homebrew installs (#188) check the tap formula and `/update` runs `brew upgrade`. There is
  no cargo channel.

## Parity tracking

The Rust test suite is the feature specification. `parity/manifest.tsv` lists every Rust
test (`FILE::NAME`) with a status: `test` (a D unittest carries a `// rust: FILE::NAME`
marker), `claimed` (ported per this file, no linked test yet), `gap` (not ported; the note
says what's missing), `na` (doesn't apply; the note says why) or `todo` (not triaged).
The Rust code is frozen at the `rust-final` tag, so CI no longer runs the check; the manifest
is the record of the port. `scripts/check-parity.py --ref rust-final` still checks it, and fails when:

- Rust gains a test the manifest doesn't list (`--update` adds it as `todo`);
- a `test` row has no marker, or a marker isn't backed by a `test` row;
- Rust commits touched `src/` after `parity/BASELINE` (triage them, then move it);
- `todo` + `claimed` rises above `parity/budget` (a ratchet: lower it, never raise it).

So a new Rust feature can't land unnoticed, and "ported" means a named D test. To port a
behaviour: write the D unittest, put the marker on the line above it, set the row to `test`.

## Not ported yet (by Rust module)

Roughly in dependency order. Sizes are Rust lines.

1. ~~**Agent loop features**~~: modes and turn caps, `report_outcome`, `/queue`, reminders, context accounting with auto/smart compaction and the history tools are all ported. An output cap learned from a provider error (`max_tokens: N > M`) lowers later requests' `max_tokens` until `/model` switches, as in Rust. Rust keeps it in memory only, like D. An error without a number halves the budget actually sent, with a floor of 1024.
2. ~~**Permissions vs. sandbox**~~: file-tool writes are held to the sandbox's writable roots (lexical and symlink-resolved path), as in Rust.
